## What this repo is

AvianVisitors is a fork of [BirdNET-Pi](https://github.com/mcguirepr89/BirdNET-Pi) (branch `avian-visitors`) that adds a live bird-collage web overlay on top of BirdNET-Pi's Raspberry Pi bird-sound-ID stack. **Everything under `avian/` and `frame/` is this project's own code.** Everything else at the repo root (`scripts/`, `homepage/`, `model/`, `templates/`, `tests/`, `newinstaller.sh`, etc.) is inherited upstream BirdNET-Pi — treat it as vendored unless a task specifically calls for touching it, and check `README.upstream.md` for upstream's own docs before assuming behavior.

The product runs on a Raspberry Pi with a USB mic: BirdNET-Pi identifies bird calls, and the AvianVisitors overlay renders detections as a live illustrated collage in the browser, served by Caddy/PHP-FPM already set up by BirdNET-Pi. There's also an optional e-ink wall frame (`frame/`) that mirrors the collage to a physical display.

## Repo layout

```
scripts/, homepage/, model/, templates/, tests/  # upstream BirdNET-Pi (Python analysis engine, PHP web UI, tflite models)
```

## Frontend architecture (`avian/frontend/`)

This is the part of the repo most actively worked on. No build step — plain HTML/CSS/JS served directly.

- `index.html` — page shell.
- `apt.js` — all collage logic: fetches detections, lays out the mask-packed circular collage, handles touch/click interactions, species detail modal, polling/refresh logic.
- `styles.css` — all styling, including responsive/coarse-pointer (tablet/iPad) rules.
- `dims.json` / `masks.json` — precomputed per-illustration dimensions and collage-packing silhouette masks. Generated by `avian/scripts/build_masks.py`, **not hand-edited**. `apt.js` fetches these at load.
- `nest.webp` — empty-state illustration when no birds have been heard (current runtime uses a CSS-drawn `.nest-mark`, not an image, for this state — check current code before assuming which is active).

**Cache-busting convention:** `apt.js` defines `SKETCH_VERSION` and `IMG_VERSION` constants near the top, appended as `?v=` query strings to asset URLs (masks/dims and illustrations respectively). Bump these when illustration assets change, per the convention documented in `avian/scripts/README.md`.

**Deploy mapping:** BirdNET-Pi's installer (`scripts/install_services.sh`) symlinks `avian/` and the individual frontend files (`index.html`, `styles.css`, `apt.js`, `masks.json`, `dims.json`, `nest.webp`) into the Caddy webroot at install time — there is no separate build/copy step. The collage is served at `/`, BirdNET-Pi's own stock UI at `/index.php`.

Known encoding hazard: this repo has been edited from a Windows/PowerShell environment before, which previously introduced UTF-8 BOM and mojibake (e.g. `→` → `â†’`) into `index.html`/`README.md`. When editing these files, verify encoding stays clean UTF-8 without BOM.

## Illustration pipeline (`avian/scripts/`)

Four-stage pipeline to (re)generate the bundled bird illustrations (kachō-e style, generated not hand-drawn):

1. `pregen.py` — renders each bird via Gemini 2.5 Flash Image on a flat cream background (`GEMINI_API_KEY` required; optionally `EBIRD_API_KEY` to filter by `--ebird-region`).
2. `cutout.py` — removes the cream ground with BiRefNet, crops to the bird.
3. `build_masks.py` — rebuilds `avian/frontend/dims.json` + `masks.json` from the cutouts. Run this after any illustration change, then bump `SKETCH_VERSION`/`IMG_VERSION` in `apt.js`.
4. `verify.py` — optional adversarial species-ID + anatomy check via Gemini Vision, catches species drift (e.g. a swift rendered as a swallow).

Prompt/style lives in `avian/scripts/prompt.template.md`; per-species correction notes live in `avian/scripts/species-notes.json` (append to, don't overwrite, when fixing a specific species' drift). Setup: `pip install -r avian/scripts/requirements.txt`.

## PHP API shims (`avian/api/`)

Small whitelisted endpoints that ride on BirdNET-Pi's existing PHP-FPM/Caddy — not a standalone service. E.g. `config.php` exposes a whitelisted read/write subset of `birdnet.conf` to the admin overlay, restarting `birdnet_analysis`/`birdnet_recording` on write (needs passwordless sudo for the caddy user, granted by `install_services.sh` via `/etc/sudoers.d/020_avian-admin`). Default LAN deploy has no auth; forwarded/public deploys should set `AV_REQUIRE_AUTH=1` and add Caddy `basic_auth` (see `avian/forwarding/caddy-auth.caddy`).

## Upstream Python analysis code (`scripts/utils/`)

The BirdNET-Pi analysis engine (`scripts/utils/analysis.py`, `db.py`, `notifications.py`, etc.) is upstream code, covered by `tests/`. Tests import it as `scripts.utils.*`, so run pytest from the repo root.

## Commands

```bash
# Python tests (upstream BirdNET-Pi analysis code; run from repo root)
pytest
pytest tests/test_analysis.py::TestRunAnalysis::test_run_analysis   # single test

# Lint (flake8 config: max-line-length=160, max-complexity=15)
flake8

# Illustration pipeline (from avian/scripts/)
python3 pregen.py --labels ~/BirdNET-Pi/model/labels.txt --ebird-region US-CA
python3 cutout.py
python3 build_masks.py
python3 verify.py --labels labels.txt
```

There is no frontend build/lint/test tooling — `avian/frontend/` is validated by loading it in a browser (desktop + iPad/Safari are both relevant targets given past layout bugs there; coarse-pointer-specific CSS/JS paths exist).

CI (`.github/workflows/python-ci.yml`, `python-app.yml`) runs flake8 and pytest against `**.py` changes on PRs to `main` — note the default branch for PRs upstream is `main` even though this fork's active branch is `avian-visitors`.
